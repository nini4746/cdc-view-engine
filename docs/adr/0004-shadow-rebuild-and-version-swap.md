# 0004. 섀도 KafkaStreams로 재구축하고 서빙 버전 하나만 교체

- 상태: 채택
- 날짜: 2026-07-07

## 맥락
스키마나 뷰 정의가 바뀌면 뷰를 처음부터 다시 만들어야 합니다.
재구축 중에도 기존 뷰 조회가 끊기지 않아야 하고, 조회 결과에 신/구 버전이 섞이면 안 됩니다.
재구축 트리거는 수동 REST 엔드포인트로 정했습니다.

## 결정
- `KafkaShadowBuilder`가 새 `application.id`의 별도 `KafkaStreams`를 earliest부터 띄워 새 버전 store(`view-{name}-v{N+1}`)를 만듭니다.
- 라이브를 따라잡으면 레지스트리의 서빙 버전 값(단일 volatile 참조) 하나를 교체하고 구버전을 정리합니다.
- 뷰 미참조 컬럼 추가는 재구축 없이 통과합니다. 뷰가 참조하는 컬럼 삭제는 명시적 에러로 거부합니다.
- 재구축 도중 재시작하면 미완의 섀도는 버리고 구버전 서빙을 유지합니다. 재개는 범위 밖입니다.

## 대안
- 기존 인스턴스 안에서 재처리: 기존 뷰 서빙과 상태가 섞입니다.
- 단계별 부분 교체: 조회가 신/구 버전을 섞어 읽을 수 있습니다.

## 결과
- 장점: 기존 토폴로지 빌더를 그대로 씁니다. CDC 토픽에 초기 스냅샷(`op=r`)부터 이력이 있어 earliest 재생만으로 재구축됩니다. 실패/중단 시 기존 서빙에 영향이 없습니다.
- 단점/감수한 점: 중단된 섀도는 이어서 만들지 못하고 재요청 시 처음부터 다시 만듭니다.
