# 0005. 재구축 진행 상태를 메모리에만 보관

- 상태: 대체됨 (0007)
- 날짜: 2026-07-07

## 맥락
재구축(0004)은 비동기로 돌고, 운영자는 진행 상태를 조회해야 합니다.
Plan 09는 재시작 시 미완의 섀도를 버리는 단순 전략을 택했고, 상태를 내부 토픽이나 로컬 파일에 기록하지 않기로 했습니다.

## 결정
- `RebuildService`가 뷰별 상태를 `ConcurrentHashMap`에 두고 단일 `rebuild-worker` 스레드에서 파이프라인을 실행합니다.

## 대안
- 상태를 내부 토픽이나 로컬 파일에 기록: Plan 09에서 단순 전략을 위해 택하지 않았습니다.

## 결과
- 장점: 추가 저장소나 스키마가 없습니다.
- 단점/감수한 점: 재구축 도중 크래시하면 상태가 모두 사라집니다. 재시작 후 상태 조회는 조용히 IDLE을 반환해, 운영자가 재구축이 진행 중이었는지 알 수 없었습니다. 이 문제로 0007로 대체되었습니다.
